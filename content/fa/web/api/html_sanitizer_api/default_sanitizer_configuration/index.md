{{DefaultAPISidebar("HTML Sanitizer API")}}

پیکربندی پیش‌فرض sanitizer مشخص می‌کند که [سازندهٔ `Sanitizer()`](/en-US/docs/Web/API/Sanitizer/Sanitizer) در صورتی که هیچ `configuration` به‌عنوان آرگومان ارسال نشود، چه پیکربندی‌ای را برمی‌گرداند. اگر [متدهای پاک‌سازی امن](/en-US/docs/Web/API/HTML_Sanitizer_API#sanitization_methods) مانند {{domxref("Element.setHTML()")}}، {{domxref("ShadowRoot.setHTML()")}} و {{domxref("Document.parseHTML_static","Document.parseHTML()")}} را بدون تعیین یک sanitizer سفارشی فراخوانی کنید، همین پیکربندی به‌صورت ضمنی استفاده می‌شود.

این پیکربندی انواع موارد زیر را حذف می‌کند:

1. مواردی که از نظر XSS ناامن شناخته می‌شوند:
   - {{htmlelement("base")}}، {{htmlelement("embed")}}، {{htmlelement("frame")}}، {{htmlelement("iframe")}}، {{htmlelement("object")}}، {{htmlelement("script")}} و {{SVGElement("use")}}.
   - همهٔ ویژگی‌های محتوایی (content attribute) مدیریت رویداد، مانند `onafterprint`، `onbeforeinput` و غیره.
2. مواردی که ممکن است در حملات clickjacking (کلیک‌دزدی)، spoofing (جعل) یا سایر حملات مورد استفاده قرار گیرند.
3. موارد منسوخ.
4. نظرات و ویژگی‌های `data-*`.

بنابراین، این پیکربندی یک sanitizer با حداقل سطح حمله ارائه می‌دهد که همچنان برای اکثر موارد استفاده از پاک‌سازی مناسب است.

> [!NOTE]
> فراخوانی {{domxref("Sanitizer.removeUnsafe()")}} یا ارسال یک sanitizer سفارشی به متد پاک‌سازی امن، تنها موارد ناامن از نظر XSS را حذف می‌کند.
> این کار موارد اضافی، نظرات و ویژگی‌های `data-*` را حذف نمی‌کند.

در بخش‌های زیر، همهٔ عناصر فهرست شده‌اند؛ علامت &check; نشان‌دهندهٔ عناصری است که توسط پیکربندی پیش‌فرض _مجاز_ هستند (و بنابراین ❌ نشان‌دهندهٔ عناصری است که حذف خواهند شد). ستون «ویژگی‌های مجاز اضافی» ویژگی‌هایی را فهرست می‌کند که برای عناصر متناظر مجاز هستند؛ هر ویژگی دیگری روی آن عنصر حذف می‌شود (مگر اینکه توسط ویژگی‌های سراسری مجاز باشد). بخش [ویژگی‌های سراسری](#global_attributes) ویژگی‌هایی را فهرست می‌کند که روی همهٔ عناصر مجاز هستند (یعنی ویژگی‌هایی که هنگام استفاده از این پیکربندی حذف نمی‌شوند).
