کلیدواژهٔ **`prefetch`** برای attribute `rel` در عنصر `<link>` به مرورگرها اشاره می‌کند که کاربر احتمالاً به منبع مدنظر در ناوبری‌های آینده نیاز خواهد داشت؛ بنابراین مرورگر می‌تواند با واکشی و کش کردن از قبلِ منبع، تجربهٔ کاربری را بهبود بخشد.

از `<link rel="prefetch">` برای منابع ناوبری در همان سایت، یا زیرمنبع‌هایی که صفحات همان سایت استفاده می‌کنند، استفاده می‌شود.

نتیجه در کش HTTP روی دیسک نگهداری می‌شود. به همین دلیل برای از پیش واکشی کردن زیرمنبع‌ها مفید است، حتی اگر در صفحهٔ فعلی استفاده نشوند. همچنین می‌توانید از آن برای پیش‌واکشی سند بعدی که کاربر احتمالاً در سایت بازدید می‌کند استفاده کنید. اما در نتیجه باید مراقب هدرها باشید — برای مثال برخی هدرهای `Cache-Control` مانند `no-cache` یا `no-store` می‌توانند prefetch را مسدود کنند.

> [!NOTE]
> به دلیل این محدودیت‌ها، توصیه می‌شود در جاهایی که پشتیبانی می‌شود برای prefetch کردن اسناد به جای آن از [Speculation Rules API](/en-US/docs/Web/API/Speculation_Rules_API) استفاده کنید.

`<link rel="prefetch">` از نظر عملکردی معادل فراخوانی `fetch()` با گزینهٔ `priority: "low"` است، به‌جز اینکه در حالت اول معمولاً اولویت حتی پایین‌تری در نظر گرفته می‌شود و هدر `Sec-Purpose: prefetch` روی درخواست تنظیم می‌شود. توجه داشته باشید که مرورگرها معمولاً به منابع prefetch اولویت کمتری نسبت به منابع preload می‌دهند (مثلاً آن‌هایی که با `<link rel="preload">` درخواست می‌شوند) — صفحهٔ فعلی مهم‌تر از صفحهٔ بعدی است.

درخواست fetch برای یک عملیات `prefetch` منجر به یک درخواست HTTP می‌شود که شامل هدر `Sec-Purpose: prefetch` است. سرور می‌تواند از این هدر برای تغییر زمان انقضای کش منابع یا انجام پردازش‌های ویژهٔ دیگر استفاده کند. درخواست همچنین شامل هدر `Sec-Fetch-Dest` با مقدار `empty` خواهد بود.

هدر `Accept` در درخواست با مقداری که برای درخواست‌های ناوبری عادی استفاده می‌شود مطابقت دارد. این کار به مرورگر اجازه می‌دهد پس از ناوبری، منابع کش‌شدهٔ منطبق را پیدا کند.

## مثال‌ها

### پیش‌واکشی پایه

```js
<link rel="prefetch" href="main.js" />
```

### prefetch ناوبری و زیرمنبع‌ها

از prefetch می‌توان برای واکشی هم HTML و هم زیرمنبع‌های یک ناوبری احتمالی بعدی استفاده کرد. یک کاربرد رایج این است که صفحهٔ فرود وب‌سایت منابع «سنگین‌تری» را که بقیهٔ سایت استفاده می‌کنند واکشی کند.

```html
<link rel="prefetch" href="/app/style.css" />
<link rel="prefetch" href="/landing-page" />
```

### اثر پارتیشن‌بندی کش

بسیاری از مرورگرها اکنون نوعی پارتیشن‌بندی کش را پیاده‌سازی می‌کنند که `<link rel="prefetch">` را برای منابعی که قرار است در سایت‌های top-level مختلف استفاده شوند بی‌فایده می‌کند. این شامل سند اصلی هنگام ناوبری بین‌سایتی نیز می‌شود. بنابراین، برای مثال، prefetch زیر:

```html
<link rel="prefetch" href="https://news.example/article" />
```

از `https://aggregator.example/` قابل دسترس نخواهد بود.

## همچنین ببینید

- برای مقایسهٔ `<link rel="prefetch">` با سایر ویژگی‌های مشابه بهبود عملکرد، به [Speculative loading](/en-US/docs/Web/Performance/Guides/Speculative_loading) مراجعه کنید.
