مقدار **`viewport`** برای attribute [`name`](/en-US/docs/Web/HTML/Reference/Elements/meta/name) در element `<meta>`، نکاتی درباره نحوه اندازه‌دهی viewport ارائه می‌دهد.

اگر مشخص شده باشد، رفتارهای مرتبط با viewport را با استفاده از attribute [`content`](/en-US/docs/Web/HTML/Reference/Elements/meta#content) در element `<meta>` و به‌صورت فهرستی با کاما از یک یا چند مقدار تعریف می‌کنید.

## نکات استفاده

element `<meta name="viewport">` attributeهای اضافی زیر را دارد:

- [`content`](/en-US/docs/Web/HTML/Reference/Elements/meta#content)
  - : ویژگی `content` حتماً باید تعریف شود و مقدار آن رفتارهای مرتبط با viewport را تعیین می‌کند. مقدار آن یک لیست جدا شده با کاما از یک یا چند کلید-مقدار (key-value pair) است که به صورت `key=value` نوشته می‌شود. کلیدهای زیر تعریف شده‌اند:
    - `width`
      - : عرض (حداقل) viewport را بر حسب پیکسل کنترل می‌کند (به [عرض viewport و عرض صفحه](#viewport_width_and_screen_width) مراجعه کنید). می‌توان آن را یک عدد صحیح مثبت بین ۱ تا ۱۰۰۰۰ پیکسل (مثل `width=600`) یا مقدار ویژه `device-width` (اندازه فیزیکی صفحه دستگاه بر حسب پیکسل CSS) قرار داد. این مقدار مقدار واحد [`vw`](/en-US/docs/Web/CSS/Reference/Values/length#relative_length_units_based_on_viewport) را تعیین می‌کند.
    - `height`
      - : ارتفاع (حداقل) viewport را بر حسب پیکسل کنترل می‌کند (به [عرض viewport و عرض صفحه](#viewport_width_and_screen_width) مراجعه کنید). می‌توان آن را یک عدد صحیح مثبت بین ۱ تا ۱۰۰۰۰ پیکسل (مثل `height=400`) یا مقدار ویژه `device-height` (اندازه فیزیکی صفحه دستگاه بر حسب پیکسل CSS) قرار داد. این مقدار مقدار واحد [`vh`](/en-US/docs/Web/CSS/Reference/Values/length#relative_length_units_based_on_viewport) را تعیین می‌کند.
    - `initial-scale`
      - : نسبت بین عرض دستگاه (`device-width` در حالت عمودی یا `device-height` در حالت افقی) و اندازه viewport را تعریف می‌کند. می‌تواند عددی بین `0.0` و `10.0` باشد.
    - `maximum-scale`
      - : حداکثر میزان بزرگنمایی (zoom in) را تعریف می‌کند. باید بزرگتر یا مساوی `minimum-scale` باشد، در غیر این صورت رفتار نامشخص است. تنظیمات مرورگر ممکن است این قانون را نادیده بگیرند و iOS10+ نیز به طور پیش‌فرض آن را نادیده می‌گیرد. می‌تواند عددی بین `0.0` و `10.0` باشد.
    - `minimum-scale`
      - : حداقل میزان بزرگنمایی را تعریف می‌کند. باید کوچکتر یا مساوی `maximum-scale` باشد، در غیر این صورت رفتار نامشخص است. تنظیمات مرورگر ممکن است این قانون را نادیده بگیرند و iOS10+ نیز به طور پیش‌فرض آن را نادیده می‌گیرد. می‌تواند عددی بین `0.0` و `10.0` باشد.
    - `user-scalable`
      - : یک مقدار بولین که مشخص می‌کند آیا کاربر می‌تواند صفحه وب را بزرگنمایی کند یا خیر. تنظیمات مرورگر ممکن است این قانون را نادیده بگیرند و iOS10+ نیز به طور پیش‌فرض آن را نادیده می‌گیرد. می‌تواند `yes` یا `no` باشد و مقدار پیش‌فرض `yes` است.
        > [!WARNING]
        > غیرفعال کردن قابلیت بزرگنمایی با تنظیم `user-scalable` به `no`، مانع از خواندن و درک محتوای صفحه توسط افرادی با مشکلات بینایی می‌شود. علاوه بر این، WCAG حداقل بزرگنمایی ۲ برابر را الزامی می‌کند، اما بهترین روش فعال‌سازی بزرگنمایی ۵ برابر است. برای اطلاعات بیشتر به موارد زیر مراجعه کنید:
        >
        > - [MDN Understanding WCAG, Guideline 1.4 explanations](/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Perceivable#guideline_1.4_make_it_easier_for_users_to_see_and_hear_content_including_separating_foreground_from_background)
        > - [Understanding Success Criterion 1.4.4 | W3C Understanding WCAG 2.0](https://www.w3.org/TR/UNDERSTANDING-WCAG20/visual-audio-contrast-scale.html)
    - `interactive-widget`
      - : تأثیر ابزارهای تعاملی UI مانند صفحه‌کلید مجازی بر viewport صفحه را مشخص می‌کند. می‌تواند یکی از کلیدواژه‌های `resizes-visual`، `resizes-content` یا `overlays-content` باشد.
        - `resizes-visual`: {{Glossary("visual viewport")}} توسط ابزار تعاملی تغییر اندازه می‌دهد. این مقدار پیش‌فرض است.
        - `resizes-content`: {{Glossary("viewport")}} توسط ابزار تعاملی تغییر اندازه می‌دهد.
        - `overlays-content`: نه viewport و نه visual viewport توسط ابزار تعاملی تغییر اندازه نمی‌دهند.

        وقتی {{Glossary("viewport")}} تغییر اندازه می‌دهد، [containing block](/en-US/docs/Web/CSS/Guides/Display/Containing_block) اولیه نیز تغییر اندازه می‌دهد و در نتیجه اندازه محاسبه‌شده [viewport units](/en-US/docs/Web/CSS/Reference/Values/length#relative_length_units_based_on_viewport) تحت تأثیر قرار می‌گیرد.

- `viewport-fit`
  - : بخش‌های قابل مشاهدهٔ صفحهٔ وب را تعریف می‌کند. این مقدار می‌تواند یکی از کلیدواژه‌های `auto`، `contain` یا `cover` باشد.
    - `auto`: روی viewport اولیهٔ چیدمان تأثیری نمی‌گذارد و کل صفحهٔ وب قابل مشاهده است.
    - `contain`: viewport طوری مقیاس‌بندی می‌شود که بزرگ‌ترین مستطیل محاط‌شده در نمایشگر را پر کند.
    - `cover`: viewport برای پر کردن صفحهٔ نمایش دستگاه مقیاس‌بندی می‌شود. توصیهٔ اکید می‌شود از متغیرهای [safe area inset](/en-US/docs/Web/CSS/Reference/Values/env) استفاده کنید تا محتوای مهم خارج از نمایشگر قرار نگیرد.

### عرض viewport و عرض صفحهٔ نمایش

viewport مرورگر، ناحیه‌ای از پنجره است که محتوای وب در آن دیده می‌شود. اندازهٔ viewport باید پیش از چیدمان محتوای صفحه محاسبه شود. ممکن است صفحه از viewport سرریز شود؛ در این حالت مرورگر نوار اسکرول در اختیار کاربر می‌گذارد تا بتواند در صفحه حرکت کند و به همهٔ محتوا دسترسی داشته باشد. اما اندازهٔ viewport معیاری است برای اینکه محتوا در چه فضایی — به‌ویژه در جهت افقی — جای بگیرد.

برخی دستگاه‌های موبایل و صفحه‌نمایش‌های باریک دیگر، صفحه‌ها را در یک پنجره یا viewport مجازی که از خود صفحه‌نمایش عریض‌تر است رندر می‌کنند و سپس نتیجهٔ رندر را برای تناسب با اندازهٔ صفحه کوچک می‌کنند. کاربران می‌توانند برای دیدن دقیق‌تر بخش‌های مختلف صفحه، بزرگ‌نمایی یا پیمایش کنند. مثلاً اگر عرض صفحهٔ موبایل 640px باشد، صفحه‌ها ممکن است با viewport مجازی 980px رندر شوند و بعد برای جا شدن در فضای 640px کوچک شوند.

این کار به این دلیل انجام می‌شود که همهٔ صفحه‌ها برای موبایل بهینه نیستند و وقتی با عرض viewport کم رندر می‌شوند، می‌شکنند یا حداقل ظاهر بدی پیدا می‌کنند. این viewport مجازی راهی است برای اینکه سایت‌هایی که برای موبایل بهینه نشده‌اند، به‌طور کلی روی دستگاه‌های با صفحهٔ باریک بهتر دیده شوند.

با این حال، این سازوکار برای صفحه‌هایی که با [media queries](/en-US/docs/Web/CSS/Guides/Media_queries) برای صفحه‌های باریک بهینه شده‌اند چندان خوب نیست؛ مثلاً اگر viewport مجازی 980px باشد، media queryهایی که در عرض 640px یا 480px یا کمتر فعال می‌شوند هرگز استفاده نخواهند شد و این اثربخشی تکنیک‌های طراحی واکنش‌گرا را محدود می‌کند.

المان `<meta>` با `viewport` این مشکل viewport مجازی را در دستگاه‌های دارای صفحهٔ باریک کاهش می‌دهد.

رایج‌ترین تنظیم به صورت زیر است؛ این تنظیم viewport را با عرض دستگاه هماهنگ می‌کند و محتوا را با بزرگ‌نمایی ۱۰۰٪ نمایش می‌دهد:

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

سایت‌ها می‌توانند viewport خود را روی اندازهٔ مشخصی تنظیم کنند. برای مثال، تعریف `"width=320, initial-scale=1"` می‌تواند برای تطبیق دقیق با صفحهٔ کوچک یک گوشی در حالت عمودی استفاده شود. این کار وقتی مرورگر صفحه را در اندازهٔ بزرگ‌تری رندر می‌کند می‌تواند مشکل‌ساز شود. برای حل این مشکل، مرورگرها در صورت لزوم عرض viewport را گسترش می‌دهند تا صفحه در مقیاس درخواستی، صفحه‌نمایش را پر کند. این ویژگی به‌ویژه در دستگاه‌های با صفحهٔ بزرگ مفید است.

برای صفحه‌هایی که مقیاس initial یا maximum تنظیم می‌کنند، این یعنی خاصیت `width` در واقع به یک _حداقل_ عرض viewport تبدیل می‌شود. مثلاً اگر چیدمان شما حداقل به ۵۰۰ پیکسل عرض نیاز دارد، می‌توانید از مارکاپ زیر استفاده کنید. وقتی صفحه‌نمایش پهن‌تر از ۵۰۰ پیکسل باشد، مرورگر viewport را گسترش می‌دهد (به جای بزرگ‌نمایی) تا با صفحه‌نمایش هماهنگ شود:

```html
<meta name="viewport" content="width=500, initial-scale=1" />
```

### تراکم صفحه‌نمایش

وضوح صفحه‌نمایش‌ها آنقدر بالا رفته که پیکسل‌های منفرد با چشم غیرمسلح قابل تشخیص نیستند. مثلاً گوشی‌های هوشمند اغلب صفحه‌های کوچکی با وضوح بالاتر از ۱۹۲۰–۱۰۸۰ پیکسل (حدود 400dpi) دارند. به همین دلیل، بسیاری از مرورگرها می‌توانند صفحه‌ها را در اندازهٔ فیزیکی کوچک‌تری نمایش دهند؛ به این صورت که به ازای هر «پیکسل» CSS، چند پیکسل سخت‌افزاری در نظر می‌گیرند. در ابتدا این موضوع باعث بروز مشکلات کاربری و خوانایی در بسیاری از وب‌سایت‌های بهینه‌شده برای لمس شد.

در صفحه‌نمایش‌های با تراکم بالا (high dpi)، مرورگرها صفحاتی که `initial-scale=1` دارند را به‌طور مؤثری بزرگ‌نمایی می‌کنند. در این حالت متن‌ها نرم و شفاف دیده می‌شوند، اما تصاویر بیت‌مپ ممکن است از وضوح کامل صفحه استفاده نکنند. برای داشتن تصاویر شارپ‌تر در این نمایشگرها، توسعه‌دهندگان می‌توانند تصاویر – یا کل layout – را در مقیاسی بزرگ‌تر از اندازه نهایی طراحی کنند و سپس با استفاده از CSS یا ویژگی‌های viewport آن‌ها را کوچک کنند.

نسبت پیکسل پیش‌فرض به چگالی نمایشگر بستگی دارد. در نمایشگرهایی با چگالی کمتر از ۲۰۰ dpi، این نسبت ۱.۰ است. در نمایشگرهای با چگالی بین ۲۰۰ تا ۳۰۰ dpi، نسبت ۱.۵ است. برای نمایشگرهایی با چگالی بیش از ۳۰۰ dpi، نسبت برابر است با `floor(چگالی / 150dpi)` (قسمت صحیح تقسیم). توجه داشته باشید که این نسبت پیش‌فرض فقط زمانی صادق است که مقیاس viewport برابر ۱ باشد. در غیر این صورت، رابطه بین پیکسل‌های CSS و پیکسل‌های دستگاه به سطح zoom فعلی بستگی دارد.

## مثال‌ها

### استفاده از اندازه viewport با meta

مثال زیر به مرورگر می‌گوید که صفحه باید با عرض دستگاه渲染 شود:

```html
<meta name="viewport" content="width=device-width" />
```

### استفاده از media query به همراه meta viewport

مقدار `content` زیر از چند کلیدواژه استفاده می‌کند که به مرورگر اشاره می‌کنند از حالت تمام‌صفحه استفاده کند، همراه با `viewport-fit` که به جلوگیری از ناحیه‌های بریده‌شده نمایشگر (مانند ناچ گوشی) کمک می‌کند:

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
```

### تأثیر ابزارهای UI تعاملی

ابزارهای UI تعاملی مرورگر می‌توانند اندازه viewport صفحه را تغییر دهند. رایج‌ترین چنین ابزاری، صفحه‌کلید مجازی است. برای کنترل اینکه مرورگر چه رفتار resizeای داشته باشد، property `interactive-widget` را تنظیم کنید.

به‌طور پیش‌فرض، صفحه‌کلید مجازی فقط visual viewport را تغییر اندازه می‌دهد که روی layout صفحه تأثیری ندارد. می‌توانید با تنظیم `interactive-widget` به `resizes-content` باعث شوید layout صفحه با حضور صفحه‌کلید مجازی تطبیق پیدا کند:

```html
<meta name="viewport" content="interactive-widget=resizes-content" />
```
