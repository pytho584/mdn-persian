عناصر `<input>` با نوع **`submit`** به صورت دکمه نمایش داده می‌شوند. وقتی رویداد `click` رخ دهد (معمولاً به خاطر کلیک کاربر روی دکمه)، عامل کاربر (user agent) تلاش می‌کند فرم را به سرور ارسال کند.

## مقدار (value)

ویژگی `value` در `<input type="submit">` یک رشته است که به عنوان برچسب دکمه نمایش داده می‌شود. دکمه‌ها به خودی خود مقدار واقعی دیگری ندارند. این `value` توصیف قابل دسترس (accessible description) دکمه را فراهم می‌کند.

### تنظیم ویژگی value

```html
<input type="submit" value="Send Request" />
```

### حذف ویژگی value

اگر `value` را مشخص نکنید، دکمه یک برچسب پیش‌فرض خواهد داشت که توسط عامل کاربر انتخاب می‌شود. این برچسب معمولاً چیزی مانند "Submit" یا "Submit Query" است. در اینجا نمونه‌ای از یک دکمه submit با برچسب پیش‌فرض در مرورگر شما آورده شده است:

```html
<input type="submit" />
```

## ویژگی‌های اضافی

علاوه بر ویژگی‌هایی که همه عناصر `<input>` به اشتراک دارند، دکمه‌های submit از ویژگی‌های زیر نیز پشتیبانی می‌کنند.

### formaction

یک رشته که آدرس URL ارسال داده‌ها را مشخص می‌کند. این ویژگی بر ویژگی `action` عنصر `<form>` والد اولویت دارد.

این ویژگی روی `<input type="image">` و `<button>` نیز در دسترس است.

### formenctype

یک رشته که روش رمزگذاری (encoding) داده‌های فرم را هنگام ارسال به سرور مشخص می‌کند. سه مقدار مجاز وجود دارد:

- `application/x-www-form-urlencoded`
  - : مقدار پیش‌فرض. داده‌های فرم را به صورت رشته‌ای پس از درصد-رمزگذاری (percent-encoding) متن با استفاده از الگوریتمی مانند `encodeURI()` ارسال می‌کند.
- `multipart/form-data`
  - : از API `FormData` برای مدیریت داده‌ها استفاده می‌کند و امکان ارسال فایل‌ها به سرور را فراهم می‌کند. اگر فرم شما شامل هر عنصر `<input>` با `type` برابر `file` باشد، **باید** از این نوع رمزگذاری استفاده کنید.
- `text/plain`
  - : متن ساده. بیشتر برای اشکال‌زدایی (debugging) مفید است تا بتوانید به راحتی داده‌های ارسالی را ببینید.

در صورت مشخص شدن، مقدار ویژگی `formenctype` بر ویژگی `enctype` فرم والد غلبه می‌کند.

این ویژگی روی `<input type="image">` و `<button>` نیز در دسترس است.

### formmethod

یک رشته که روش HTTP را برای ارسال داده‌های فرم مشخص می‌کند. این مقدار بر هر ویژگی `method` که روی فرم والد تنظیم شده است غلبه می‌کند. مقادیر مجاز عبارتند از:

- `get`
  - : یک URL به این صورت ساخته می‌شود: با URL ارائه‌شده توسط attribute `formaction` یا `action` شروع می‌شود، یک کاراکتر علامت سؤال (`?`) به آن اضافه می‌شود و سپس داده‌های فرم که طبق `formenctype` یا `enctype` فرم کدگذاری شده‌اند، الحاق می‌گردد. این URL با استفاده از یک درخواست HTTP GET به سرور ارسال می‌شود. این روش برای فرم‌هایی که فقط شامل کاراکترهای ASCII هستند و عوارض جانبی ندارند، مناسب است. این مقدار پیش‌فرض است.
- `post`
  - : داده‌های فرم در بدنه درخواست HTTP POST که به URL مشخص‌شده توسط `formaction` یا `action` ارسال می‌شود، قرار می‌گیرند. این روش از داده‌های پیچیده و پیوست فایل پشتیبانی می‌کند.
- `dialog`
  - : این روش نشان می‌دهد که دکمه، دیالوگی را که input به آن مربوط است می‌بندد و هیچ داده فرمی را ارسال نمی‌کند.

این attribute همچنین روی عناصر `<input type="image">` و `<button>` نیز در دسترس است.

### formnovalidate

یک attribute از نوع Boolean که در صورت وجود، مشخص می‌کند که فرم نباید قبل از ارسال به سرور اعتبارسنجی شود. این مقدار، attribute `novalidate` را روی فرم والد این عنصر نادیده می‌گیرد.

این attribute همچنین روی عناصر `<input type="image">` و `<button>` نیز در دسترس است.

### formtarget

یک رشته که نام یا کلمه کلیدی را مشخص می‌کند و نشان می‌دهد که پاسخ دریافتی پس از ارسال فرم کجا نمایش داده شود. این رشته باید نام یک **browsing context** (یعنی یک تب، پنجره یا `<iframe>`) باشد. مقداری که در اینجا مشخص می‌شود، هر targetای را که توسط attribute `target` روی `<form>` والد این input تعیین شده است، نادیده می‌گیرد.

علاوه بر نام‌های واقعی تب‌ها، پنجره‌ها یا inline frameها، چند کلمه کلیدی ویژه نیز وجود دارد:

- `_self`
  - : پاسخ را در همان browsing context که حاوی فرم است بارگذاری می‌کند. این کار سند فعلی را با داده دریافتی جایگزین می‌کند. این مقدار پیش‌فرض است اگر هیچ مقداری مشخص نشود.
- `_blank`
  - : پاسخ را در یک browsing context جدید و بدون نام بارگذاری می‌کند. معمولاً این یک تب جدید در همان پنجره سند فعلی است، اما ممکن است بسته به پیکربندی user agent متفاوت باشد.
- `_parent`
  - : پاسخ را در browsing context والد (parent) جاری بارگذاری می‌کند. اگر context والدی وجود نداشته باشد، مانند `_self` عمل می‌کند.
- `_top`
  - : پاسخ را در browsing context سطح بالا (top-level) بارگذاری می‌کند؛ این همان browsing context است که بالاترین ancestor context جاری است. اگر context جاری بالاترین context باشد، مانند `_self` عمل می‌کند.

این attribute همچنین روی عناصر `<input type="image">` و `<button>` نیز در دسترس است.

## استفاده از دکمه‌های submit

دکمه‌های `<input type="submit">` برای ارسال فرم استفاده می‌شوند. اگر می‌خواهید یک دکمه سفارشی ایجاد کنید و سپس رفتار آن را با JavaScript سفارشی‌سازی کنید، باید از `<input type="button">` استفاده کنید، یا بهتر است از یک عنصر `<button>` استفاده کنید.

اگر تصمیم دارید از عناصر `<button>` برای ایجاد دکمه‌های فرم خود استفاده کنید، این نکته را در نظر داشته باشید: اگر `<button>` درون یک `<form>` باشد، آن دکمه به عنوان دکمه "submit" در نظر گرفته می‌شود. بنابراین بهتر است عادت کنید که به صراحت مشخص کنید کدام دکمه دکمه ارسال است.

### یک دکمه submit پایه

ما با ایجاد یک فرم با یک دکمه submit پایه شروع می‌کنیم.

```html
<form>
  <div>
    <label for="example">Let's submit some text</label>
    <input id="example" type="text" name="text" />
  </div>
  <div>
    <input type="submit" value="Send" />
  </div>
</form>
```

خروجی این کد به این صورت است:

مقداری متن در فیلد متنی وارد کنید و سپس فرم را ارسال کنید.

هنگام ارسال، جفت نام/مقدار داده به سرور فرستاده می‌شود. در این مثال، رشته ارسالی `text=user-text` خواهد بود که «user-text» همان متن واردشده توسط کاربر است و برای حفظ کاراکترهای خاص کدگذاری می‌شود. مکان و روش ارسال داده به پیکربندی `<form>` بستگی دارد؛ برای جزئیات بیشتر، [ارسال داده‌های فرم](/en-US/docs/Learn_web_development/Extensions/Forms/Sending_and_retrieving_form_data) را ببینید.

### افزودن میانبر صفحه‌کلید به دکمه ارسال

میانبرهای صفحه‌کلید که به آن‌ها کلیدهای دسترسی و معادل‌های صفحه‌کلید نیز گفته می‌شود، به کاربر اجازه می‌دهند با یک کلید یا ترکیبی از کلیدها، دکمه را فعال کند. برای افزودن میانبر صفحه‌کلید به دکمه ارسال — همان‌طور که برای هر `<input>` که منطقی باشد انجام می‌دهید — از ویژگی سراسری [`accesskey`](/en-US/docs/Web/HTML/Reference/Global_attributes/accesskey) استفاده می‌کنید.

در این مثال، کلید `s` به‌عنوان کلید دسترسی تعیین شده است (باید کلید `s` را همراه با کلیدهای اصلاح‌کننده مخصوص مرورگر/سیستمعامل خود فشار دهید). برای جلوگیری از تداخل با میانبرهای خود عامل کاربر، از کلیدهای اصلاح‌کننده متفاوتی برای کلیدهای دسترسی نسبت به سایر میانبرها در رایانه میزبان استفاده می‌شود. برای جزئیات بیشتر به [`accesskey`](/en-US/docs/Web/HTML/Reference/Global_attributes/accesskey) مراجعه کنید.

مثال قبلی با افزودن کلید دسترسی `s`:

```html
<form>
  <div>
    <label for="example">Let's submit some text</label>
    <input id="example" type="text" name="text" />
  </div>
  <div>
    <input type="submit" value="Send" accesskey="s" />
  </div>
</form>
```

به‌عنوان مثال، در فایرفاکس برای مک، فشردن `Control`-`Option`-`S` دکمه Send را فعال می‌کند، در حالی که کروم در ویندوز از `Alt`+`S` استفاده می‌کند.

مشکل مثال بالا این است که کاربر نمی‌داند کلید دسترسی چیست! این موضوع به‌ویژه به این دلیل صادق است که کلیدهای اصلاح‌کننده معمولاً غیراستاندارد هستند تا از تداخل جلوگیری کنند. هنگام ساخت سایت، حتماً این اطلاعات را به‌گونه‌ای ارائه دهید که با طراحی سایت تداخل نداشته باشد (مثلاً با ارائه یک لینک در دسترس که به اطلاعات کلیدهای دسترسی سایت اشاره می‌کند). افزودن tooltip به دکمه (با استفاده از ویژگی [`title`](/en-US/docs/Web/HTML/Reference/Global_attributes/title)) نیز می‌تواند کمک کند، اگرچه برای اهداف دسترس‌پذیری راه‌حل کاملی نیست.

### غیرفعال کردن و فعال کردن دکمه ارسال

برای غیرفعال کردن دکمه ارسال، ویژگی [`disabled`](/en-US/docs/Web/HTML/Reference/Attributes/disabled) را روی آن قرار دهید، مانند:

```html
<input type="submit" value="Send" disabled />
```

می‌توانید دکمه‌ها را در زمان اجرا با تنظیم `disabled` به `true` یا `false` فعال یا غیرفعال کنید؛ در جاوااسکریپت این کار به شکل `btn.disabled = true` یا `btn.disabled = false` انجام می‌شود.

> [!NOTE]
> برای ایده‌های بیشتر درباره فعال و غیرفعال کردن دکمه‌ها، صفحه [`<input type="button">`](/en-US/docs/Web/HTML/Reference/Elements/input/button#disabling_and_enabling_a_button) را ببینید.

## اعتبارسنجی

دکمه‌های ارسال در اعتبارسنجی محدودیت‌ها مشارکت نمی‌کنند؛ مقدار واقعی برای محدود شدن ندارند.

## مثال‌ها

نمونه‌های پایه را در بالا آورده‌ایم. واقعاً چیز بیشتری برای گفتن درباره دکمه‌های ارسال وجود ندارد. دلیلی دارد که این نوع کنترل گاهی «دکمه ساده» نامیده می‌شود.
