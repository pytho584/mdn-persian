المان‌های `<input>` از نوع **`hidden`** به توسعه‌دهندگان وب اجازه می‌دهند داده‌هایی را که کاربران هنگام ارسال فرم نمی‌توانند ببینند یا تغییر دهند، در فرم قرار دهند. به عنوان مثال، شناسه محتوایی که در حال سفارش یا ویرایش است، یا یک توکن امنیتی یکتا. inputهای مخفی کاملاً در صفحه رندر شده نامرئی هستند و هیچ راهی برای نمایش آن‌ها در محتوای صفحه وجود ندارد.

> [!NOTE]
> رویدادهای `input` و `change` برای این نوع input اعمال نمی‌شوند. inputهای مخفی حتی با استفاده از JavaScript نیز نمی‌توانند فوکوس شوند (مثلاً `hiddenInput.focus()`).

## مقدار

attribute [`value`](/en-US/docs/Web/HTML/Reference/Elements/input#value) مربوط به المان `<input>` یک رشته (string) نگه می‌دارد که حاوی داده مخفی‌ای است که می‌خواهید هنگام ارسال فرم به سرور ارسال شود. این مقدار به‌طور خاص توسط کاربر از طریق رابط کاربری قابل ویرایش یا مشاهده نیست، اگرچه می‌توانید آن را از طریق ابزارهای توسعه‌دهنده مرورگر ویرایش کنید.

> [!WARNING]
> اگرچه مقدار در محتوای صفحه به کاربر نمایش داده نمی‌شود، اما با ابزارهای توسعه‌دهنده هر مرورگر یا قابلیت «View Source» قابل مشاهده و ویرایش است. برای امنیت به inputهای `hidden` تکیه نکنید.

## attributeهای اضافی

علاوه بر attributeهای مشترک بین همه المان‌های `<input>`، inputهای `hidden` attributeهای زیر را دارند.

### name

این در واقع یکی از attributeهای مشترک است، اما برای inputهای hidden معنای ویژه‌ای دارد. به‌طور معمول، attribute [`name`](/en-US/docs/Web/HTML/Reference/Elements/input#name) در inputهای hidden دقیقاً مثل سایر inputها عمل می‌کند. اما وقتی فرم ارسال می‌شود، یک input مخفی که `name` آن `_charset_` تنظیم شده باشد، به‌طور خودکار با مقدار encoding کاراکتری که برای ارسال فرم استفاده شده گزارش می‌شود.

## استفاده از inputهای مخفی

همانطور که در بالا اشاره شد، inputهای hidden را می‌توان در هر جایی استفاده کرد که بخواهید داده‌ای را که کاربر نمی‌تواند ببیند یا ویرایش کند، همراه با فرم هنگام ارسال به سرور قرار دهید. بیایید چند مثال را ببینیم که کاربرد آن را نشان می‌دهد.

### پیگیری محتوای ویرایش‌شده

یکی از رایج‌ترین کاربردهای inputهای hidden، پیگیری این است که کدام رکورد از پایگاه داده باید هنگام ارسال فرم ویرایش، به‌روزرسانی شود. یک روند معمولی به این شکل است:

1. کاربر تصمیم می‌گیرد محتوایی را که کنترل آن را دارد ویرایش کند، مثلاً یک پست وبلاگ یا یک محصول. او با زدن دکمه ویرایش شروع می‌کند.
2. محتوایی که قرار است ویرایش شود از پایگاه داده گرفته می‌شود و در یک فرم HTML بارگذاری می‌شود تا کاربر بتواند تغییرات را اعمال کند.
3. پس از ویرایش، کاربر فرم را ارسال می‌کند و داده به‌روزرسانی‌شده برای به‌روزرسانی در پایگاه داده به سرور بازگردانده می‌شود.

ایده این است که در مرحله ۲، شناسه (ID) رکوردی که در حال به‌روزرسانی است در یک input مخفی نگه داشته می‌شود. وقتی فرم در مرحله ۳ ارسال می‌شود، ID به‌طور خودکار همراه با محتوای رکورد به سرور بازگردانده می‌شود. ID به بخش سمت سرور سایت اجازه می‌دهد دقیقاً بداند کدام رکورد باید با داده ارسال‌شده به‌روزرسانی شود.

در بخش [Examples](#examples) در پایین می‌توانید یک مثال کامل از این مورد را ببینید.

### بهبود امنیت وب‌سایت

inputهای hidden همچنین برای ذخیره و ارسال توکن‌های امنیتی یا _رازها_ (secrets) به منظور بهبود امنیت وب‌سایت استفاده می‌شوند. ایده اصلی این است که اگر کاربر در حال پر کردن یک فرم حساس است، مثل فرمی در وب‌سایت بانک برای انتقال پول به حساب دیگر، رازی که به او داده می‌شود ثابت می‌کند که او همان کسی است که ادعا می‌کند و از فرم صحیح برای ارسال درخواست انتقال استفاده می‌کند.

این کار باعث می‌شود یک کاربر مخرب نتواند فرم جعلی‌ای بسازد که مثلاً خودش را جای بانک جا بزند، آن را برای کاربران بی‌خبر ایمیل کند و آنها را فریب دهد تا پول را به جای اشتباهی منتقل کنند. به این نوع حمله [Cross Site Request Forgery (CSRF)](/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Website_security#cross-site_request_forgery_csrf) می‌گویند؛ تقریباً همهٔ فریم‌ورک‌های معتبر سمت سرور از این نوع رازهای پنهان برای جلوگیری از چنین حملاتی استفاده می‌کنند.

> [!NOTE]
> قرار دادن راز در یک input پنهان به خودیِ خود امنیت ایجاد نمی‌کند؛ ترکیب و رمزنگاری کلید است که امنیت را تأمین می‌کند. ارزش این input پنهان در این است که راز را با داده‌ها همراه نگه می‌دارد و هنگام ارسال فرم به سرور، آن را به‌صورت خودکار شامل می‌شود. برای امنیت واقعی وب‌سایت، باید از رازهای خوب طراحی‌شده استفاده کنید.

## اعتبارسنجی

Input های پنهان در اعتبارسنجی محدودیت‌ها (constraint validation) شرکت نمی‌کنند؛ چون مقدار واقعی‌ای ندارند که محدود شود.

## مثال‌ها

بیایید ببینیم چگونه می‌توانیم نسخه‌ای از فرم ویرایش را که قبلاً توضیح داده شد پیاده‌سازی کنیم (به [ردیابی محتوای ویرایش‌شده](#tracking_edited_content) مراجعه کنید) و از یک input پنهان برای به خاطر سپردن شناسهٔ رکورد در حال ویرایش استفاده کنیم.

HTML فرم ویرایش می‌تواند چیزی شبیه این باشد:

```html
<form>
  <div>
    <label for="title">Post title:</label>
    <input type="text" id="title" name="title" value="My excellent blog post" />
  </div>
  <div>
    <label for="content">Post content:</label>
    <textarea id="content" name="content" cols="60" rows="5">
This is the content of my excellent blog post. I hope you enjoy it!
    </textarea>
  </div>
  <div>
    <button type="submit">Update post</button>
  </div>
  <input type="hidden" id="postId" name="postId" value="34657" />
</form>
```

و چند CSS هم اضافه می‌کنیم:

```css
html {
  font-family: sans-serif;
}

form {
  width: 500px;
}

div {
  display: flex;
  margin-bottom: 10px;
}

label {
  flex: 2;
  line-height: 2;
  text-align: right;
  padding-right: 20px;
}

input,
textarea {
  flex: 7;
  font-family: sans-serif;
  font-size: 1.1rem;
  padding: 5px;
}

textarea {
  height: 60px;
}
}

سرور قبل از ارسال فرم به مرورگر کاربر، مقدار input پنهان با شناسهٔ `postID` را روی شناسهٔ پست در پایگاه‌داده خود تنظیم می‌کند و وقتی فرم برگردانده شد، از این اطلاعات استفاده می‌کند تا بفهمد کدام رکورد پایگاه‌داده باید با اطلاعات تغییر یافته به‌روزرسانی شود. برای این کار نیازی به اسکریپت‌نویسی در محتوا نیست.

خروجی به این شکل است:

> [!NOTE]
> می‌توانید این مثال را در GitHub هم ببینید (کد منبع را [اینجا](https://github.com/mdn/learning-area/blob/main/html/forms/hidden-input-example/index.html) و اجرای زندهٔ آن را [اینجا](https://mdn.github.io/learning-area/html/forms/hidden-input-example/index.html) مشاهده کنید).

وقتی فرم ارسال شود، داده‌هایی که به سرور می‌روند چیزی شبیه این خواهند بود:

`title=My+excellent+blog+post&content=This+is+the+content+of+my+excellent+blog+post.+I+hope+you+enjoy+it!&postId=34657`

اگرچه input پنهان اصلاً دیده نمی‌شود، داده‌های آن همچنان ارسال می‌شوند.

| ویژگی | توضیح |
|---|---|
| **مقدار (Value)** | رشته‌ای که مقدار دادهٔ پنهانی که می‌خواهید به سرور ارسال کنید را نشان می‌دهد. |
| **رویدادها (Events)** | ندارد. |
| **ویژگی‌های مشترک پشتیبانی‌شده** | [`autocomplete`](/en-US/docs/Web/HTML/Reference/Elements/input#autocomplete) |
| **ویژگی‌های IDL** | `value` |
| **رابط DOM** | `HTMLInputElement` |
| **نقش ضمنی ARIA** | [بدون نقش متناظر](https://w3c.github.io/html-aria/#dfn-no-corresponding-role) |
