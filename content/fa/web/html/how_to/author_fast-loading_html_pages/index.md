یک صفحه وب بهینه‌شده نه‌تنها سایت را برای بازدیدکنندگان واکنش‌گراتر می‌کند، بلکه بار روی سرورها و اتصال اینترنت شما را هم کاهش می‌دهد. این موضوع برای سایت‌های پربازدید یا سایت‌هایی که به‌دلیل شرایط غیرعادی مثل اخبار فوری ناگهان ترافیک‌شان بالا می‌رود، حیاتی است.  
این مقاله روش‌های بهبود زمان بارگذاری صفحه را بر اساس دانش رایج و آزمایش‌ها شرح می‌دهد.

بهینه‌سازی سرعت بارگذاری فقط برای محتوایی که کاربران با اتصال‌های کم‌سرعت Dial-up یا موبایل مشاهده می‌کنند لازم نیست؛ برای محتوای پهن‌باند هم به همان اندازه مهم است و حتی برای بازدیدکنندگانی که سریع‌ترین اتصال را دارند هم بهبود چشمگیری ایجاد می‌کند.

## نکته‌ها

### کاهش حجم صفحه (Page Weight)

حجم صفحه تا حد زیادی مهم‌ترین عامل در کارایی بارگذاری صفحه است.

کاهش حجم صفحه با حذف فاصله‌های خالی (Whitespace) و کامنت‌های غیرضروری — که معمولاً به آن Minimization می‌گویند — و انتقال اسکریپت‌های inline و CSS به فایل‌های خارجی، می‌تواند سرعت دانلود را بدون نیاز به تغییرات دیگر در ساختار صفحه بهبود دهد.

ابزارهایی مثل [HTML Tidy](https://www.html-tidy.org/) می‌توانند به‌طور خودکار فاصله‌های ابتدایی و خطوط خالی اضافی را از HTML معتبر حذف کنند. ابزارهای دیگر هم می‌توانند با تغییر قالب‌بندی یا مبهم‌سازی (Obfuscation) جاوااسکریپت و جایگزینی شناسه‌های طولانی با نسخه‌های کوتاه‌تر، آن را «فشرده» کنند.

### کاهش تعداد فایل‌ها

کاهش تعداد فایل‌هایی که در یک صفحه وب ارجاع داده می‌شوند، تعداد اتصال‌های [HTTP](/en-US/docs/Web/HTTP) لازم برای دانلود صفحه را کم می‌کند و در نتیجه زمان ارسال request ها و دریافت response ها کاهش می‌یابد.

بسته به تنظیمات کش مرورگر، مرورگر ممکن است برای هر فایل ارجاع‌شده یک درخواست با هدر [`If-Modified-Since`](/en-US/docs/Web/HTTP/Reference/Headers/If-Modified-Since) بفرستد و بپرسد که آیا فایل از آخرین باری که دانلود شده تغییر کرده است یا نه. صرف زمان زیاد برای بررسی زمان آخرین تغییر فایل‌های ارجاع‌شده می‌تواند نمایش اولیه صفحه را به تأخیر بیندازد، چون مرورگر باید قبل از رندر کردن صفحه، زمان تغییر هرکدام از این فایل‌ها را چک کند.

اگر در CSS خود زیاد از تصاویر پس‌زمینه استفاده می‌کنید، می‌توانید با ترکیب تصاویر در یک تصویر واحد — که به آن Image Sprite می‌گویند — تعداد جستجوهای HTTP را کاهش دهید. بعد هر بار که به تصویر پس‌زمینه نیاز داشتید، همان تصویر را اعمال می‌کنید و مختصات x/y را به‌درستی تنظیم می‌کنید. این روش بیشتر برای عناصری که ابعاد محدودی دارند کارایی دارد و برای همهٔ کاربردهای تصویر پس‌زمینه جواب نمی‌دهد. با این حال، تعداد کمتر درخواست‌های HTTP و کش شدن یک تصویر واحد می‌تواند زمان بارگذاری صفحه را کاهش دهد.

### استفاده از شبکه تحویل محتوا (CDN)

برای این مقاله، CDN راهی برای کاهش فاصله فیزیکی بین سرور شما و بازدیدکننده است. هرچه فاصله بین سرور مبدأ و بازدیدکننده بیشتر شود، زمان بارگذاری هم بیشتر می‌شود. فرض کنید سرور سایت شما در ایالات متحده است و یک بازدیدکننده از هند دارید؛ زمان بارگذاری صفحه برای بازدیدکننده هندی خیلی بیشتر از بازدیدکننده آمریکایی خواهد بود.

CDN شبکه‌ای از سرورها است که به‌صورت جغرافیایی توزیع شده‌اند و با هم کار می‌کنند تا فاصله بین کاربر و سایت شما را کم کنند. CDN نسخه‌های کش‌شده سایت شما را ذخیره می‌کند و از طریق نزدیک‌ترین گره شبکه به کاربر به بازدیدکنندگان ارائه می‌دهد و در نتیجه [تأخیر (Latency)](/en-US/docs/Web/Performance/Guides/Understanding_latency) را کاهش می‌دهد.

### کاهش جستجوهای دامنه (Domain Lookups)

چون هر دامنه جداگانه برای DNS Lookup زمان می‌برد، با افزایش تعداد دامنه‌های مختلفی که در link های CSS، JavaScript و src تصاویر ظاهر می‌شوند، زمان بارگذاری صفحه هم بیشتر می‌شود.

این کار همیشه عملی نیست؛ با این حال، همیشه باید مراقب باشید که در صفحاتتان فقط از حداقل تعداد لازم دامنه استفاده کنید.

### استفادهٔ مجدد از محتوای کش‌شده

مطمئن شوید هر محتوایی که قابلیت کش شدن دارد، کش می‌شود و زمان انقضای مناسبی هم دارد.

به‌طور خاص، به هدر `Last-Modified` توجه کنید. این هدر امکان کش کردن کارآمد صفحه را فراهم می‌کند؛ از طریق آن، اطلاعاتی دربارهٔ فایلی که قرار است بارگذاری شود به user agent منتقل می‌شود، مثل زمان آخرین تغییر. بیشتر وب‌سرورها به‌صورت خودکار هدر `Last-Modified` را بر اساس تاریخ آخرین تغییر ذخیره‌شده در فایل‌سیستم به صفحات ایستا (مثل `.html` و `.css`) اضافه می‌کنند. در صفحات پویا (مثل `.php` یا `.aspx`) این کار ممکن نیست و این هدر ارسال نمی‌شود.

بنابراین، به‌ویژه برای صفحاتی که به‌صورت پویا تولید می‌شوند، کمی تحقیق در این زمینه مفید است. شاید کمی پیچیده باشد، اما درخواست‌های صفحه را برای صفحاتی که معمولاً قابل کش نیستند به‌شدت کاهش می‌دهد.

### ترتیب بهینهٔ اجزای صفحه

ابتدا محتوای صفحه را همراه با CSS یا JavaScript موردنیاز برای نمایش اولیه دانلود کنید، تا کاربر سریع‌ترین پاسخ ظاهری را هنگام بارگذاری صفحه دریافت کند. این محتوا معمولاً متن است و بنابراین می‌تواند از فشرده‌سازی متن در حین انتقال بهره ببرد و پاسخ سریع‌تری به کاربر بدهد.

هر ویژگی پویایی که برای استفاده به بارگذاری کامل صفحه نیاز دارد، باید ابتدا غیرفعال باشد و فقط بعد از بارگذاری صفحه فعال شود. این کار باعث می‌شود JavaScript بعد از محتوای صفحه بارگذاری شود و ظاهر کلی بارگذاری صفحه را بهبود دهد.

### کاهش تعداد اسکریپت‌های inline

اسکریپت‌های inline می‌توانند بارگذاری صفحه را پرهزینه کنند، چون parser باید فرض کند که یک اسکریپت inline ممکن است در حین parse کردن، ساختار صفحه را تغییر دهد. کاهش استفاده از اسکریپت‌های inline به‌طور کلی، و به‌ویژه کاهش استفاده از `document.write()` برای خروجی محتوا، می‌تواند بارگذاری کلی صفحه را بهبود دهد. به‌جای `document.write()` از [DOM APIs to manipulate page content](/en-US/docs/Learn_web_development/Core/Scripting/DOM_scripting) استفاده کنید.

### استفاده از CSS مدرن و نشانه‌گذاری معتبر

استفاده از CSS مدرن مقدار نشانه‌گذاری را کاهش می‌دهد، نیاز به تصاویر (فاصله‌انداز) را در چیدمان کم می‌کند و اغلب می‌تواند جایگزین تصاویرِ متنِ استایل‌شده شود — تصاویری که هزینهٔ بسیار بیشتری نسبت به ترکیب متن و CSS دارند.

نشانه‌گذاری معتبر مزایای دیگری هم دارد. اول اینکه مرورگرها نیازی به انجام اصلاح خطا هنگام parse کردن HTML ندارند (این موضوع جدا از بحث فلسفی است که آیا اجازهٔ تغییر قالب در ورودی کاربر را بدهیم و بعد آن را برنامه‌نویسی‌شده «اصلاح» یا نرمال‌سازی کنیم، یا اینکه به‌جای آن، قالب ورودی سخت‌گیرانه و بدون خطا را اعمال کنیم).

علاوه بر این، نشانه‌گذاری معتبر امکان استفادهٔ آزادانه از ابزارهایی را فراهم می‌کند که می‌توانند صفحات وب شما را _پیش‌پردازش_ کنند. برای مثال، [HTML Tidy](https://www.html-tidy.org/) می‌تواند فاصله‌های خالی و تگ‌های پایانی اختیاری را حذف کند؛ اما اگر صفحه‌ای خطاهای جدی نشانه‌گذاری داشته باشد، از اجرا شدن روی آن خودداری می‌کند.

### محتوای خود را بخش‌بندی کنید

استفاده از جدول‌ها برای چیدمان، روشی قدیمی است که دیگر نباید استفاده شود. به‌جای آن، از چیدمان‌هایی استفاده کنید که از [floats](/en-US/docs/Learn_web_development/Core/CSS_layout/Floats)، [positioning](/en-US/docs/Learn_web_development/Core/CSS_layout/Positioning)، [flexbox](/en-US/docs/Learn_web_development/Core/CSS_layout/Flexbox) یا [grids](/en-US/docs/Learn_web_development/Core/CSS_layout/Grids) استفاده می‌کنند.

جدولها هنوز مارکاپ معتبری محسوب میشوند، اما باید فقط برای نمایش دادههای جدولوار استفاده شوند. برای اینکه مرورگر صفحه را سریعتر رندر کند، بهجای تو در تو کردن جدولها از روشهای CSS مانند [Flexbox](/en-US/docs/Web/CSS/Guides/Flexible_box_layout) و [Grid layout](/en-US/docs/Web/CSS/Guides/Grid_layout) استفاده کنید.

### کوچکسازی و فشردهسازی منابع SVG

SVG تولیدشده توسط بیشتر برنامههای طراحی اغلب حاوی متادیتای غیرضروری است که میتوان آن را حذف کرد. سرورهای خود را پیکربندی کنید و فشردهسازی gzip را برای منابع SVG فعال کنید.

### کوچکسازی و فشردهسازی تصاویر

تصاویر بزرگ باعث میشوند صفحه شما زمان بیشتری برای بارگذاری نیاز داشته باشد. پیش از افزودن تصاویر به صفحه، آنها را فشرده کنید؛ میتوانید از قابلیتهای فشردهسازی داخلی ابزارهایی مثل Photoshop استفاده کنید یا از ابزار تخصصی مانند [Compress JPEG](https://compressjpeg.com/) یا [Tiny PNG](https://tinypng.com/) بهره ببرید.

### تعیین ابعاد برای تصاویر و جدولها

اگر مرورگر بتواند بلافاصله ارتفاع و/یا عرض تصاویر و جدولها را تعیین کند، میتواند صفحه وب را بدون نیاز به چیدمان دوباره محتوا نمایش دهد. این کار نهتنها نمایش صفحه را سریعتر میکند، بلکه از تغییرات آزاردهنده در چیدمان صفحه هنگام تکمیل بارگذاری نیز جلوگیری میکند. به همین دلیل، تا حد امکان باید برای تصاویر، `height` و `width` مشخص شود.

برای جدولها باید از ویژگی CSS زیر استفاده شود:

```css
table-layout: fixed;
```

و عرض ستونها را با استفاده از عناصر [`<col>`](/en-US/docs/Web/HTML/Reference/Elements/col) و [`<colgroup>`](/en-US/docs/Web/HTML/Reference/Elements/colgroup) مشخص کنید.

### استفاده از lazy loading برای تصاویر

بهطور پیشفرض، تصاویر بهصورت **eagerly** بارگذاری میشوند؛ یعنی به محض پردازش در HTML، تصویر دریافت و رندر میشود. همه تصاویری که eager بارگذاری میشوند، قبل از ارسال رویداد [`load`](/en-US/docs/Web/API/Window/load_event) پنجره رندر میگردند. تغییر به بارگذاری lazy به مرورگر میگوید که بارگذاری تصاویر را تا زمانی که برای رسم visual viewport لازم شوند به تأخیر بیندازد.

برای علامتگذاری یک تصویر برای lazy loading، ویژگی [`loading`](/en-US/docs/Web/HTML/Reference/Elements/img#loading) آن را با مقدار `lazy` مشخص کنید. با این کار، تصویر فقط زمانی بارگذاری میشود که به آن نیاز باشد.

```html
<img src="./images/footerlogo.jpg" loading="lazy" alt="MDN logo" />
```

توجه داشته باشید که تصاویر lazily-loaded ممکن است هنگام رویداد `load` در دسترس نباشند. میتوانید با بررسی اینکه مقدار خاصیت Boolean «complete» از `HTMLImageElement` برابر با `true` است، وضعیت بارگذاری یک تصویر را تعیین کنید.

### نیازمندیهای user-agent را هوشمندانه انتخاب کنید

برای دستیابی به بیشترین بهبود در طراحی صفحه، مطمئن شوید که نیازمندیهای معقولی برای user-agent در پروژهها مشخص شده است. از محتوای خود نخواهید که در همه مرورگرها، بهویژه نسخههای قدیمیتر، pixel-perfect نمایش داده شود.

در حالت ایدهآل، حداقل نیازمندیهای پایه باید بر اساس مرورگرهای مدرنی در نظر گرفته شوند که از استانداردهای مربوطه پشتیبانی میکنند. این مرورگرها میتوانند شامل نسخههای اخیر Firefox، Google Chrome، Opera و Safari باشند.

با این حال، توجه داشته باشید که بسیاری از نکات ذکرشده در این مقاله، تکنیکهای ساده و منطقی هستند که برای هر user-agent و هر صفحه وبی، صرفنظر از نیازمندیهای پشتیبانی مرورگر، قابل استفادهاند.

### در صورت امکان از async و defer استفاده کنید

اسکریپتهای جاوااسکریپت را طوری بنویسید که با ویژگیهای [`async`](/en-US/docs/Web/HTML/Reference/Elements/script#attributes) و [`defer`](/en-US/docs/Web/HTML/Reference/Elements/script#attributes) سازگار باشند و تا حد امکان، بهویژه وقتی چند عنصر `script` دارید، از [`async`](/en-US/docs/Web/HTML/Reference/Elements/script#attributes) استفاده کنید.

با این کار، صفحه میتواند در حالی که جاوااسکریپت هنوز در حال بارگذاری است، به رندر شدن ادامه دهد. در غیر این صورت، مرورگر هیچ چیزی را که بعد از عناصر `script` فاقد این ویژگیها قرار دارد، رندر نخواهد کرد.

توجه: اگرچه این ویژگی‌ها (attributes) در بارگذاری اولیه صفحه کمک زیادی می‌کنند، اما نباید فرض کنید که در تمام مرورگرها کار می‌کنند. اگر از قبل تمام بهترین روش‌های JavaScript را دنبال می‌کنید، نیازی به تغییر کد خود ندارید.

## ساختار مثال یک صفحه

- `<html>`
  - `<head>`
    - `<link>`

      فایل‌های CSS مورد نیاز برای ظاهر صفحه. برای بهبود کارایی، تعداد فایل‌ها را به حداقل برسانید، اما CSSهای نامرتبط را برای نگهداری آسان در فایل‌های جداگانه نگه دارید.

    - `<script>`

      فایل‌های JavaScript برای توابعی که **در هنگام بارگذاری صفحه** مورد نیاز هستند، نه JavaScript تعاملی که فقط پس از بارگذاری صفحه اجرا می‌شود.

      برای بهبود کارایی، تعداد فایل‌ها را به حداقل برسانید، اما JavaScriptهای نامرتبط را برای نگهداری آسان در فایل‌های جداگانه نگه دارید.

  - `<body>`

    محتوای قابل مشاهده صفحه در بخش‌های کوچک (`<header>` / `<main>` / `<table>`) که می‌توانند بدون انتظار برای دانلود کامل صفحه نمایش داده شوند.

    - `<script>`

      هر اسکریپتی که برای تعامل استفاده می‌شود. اسکریپت‌های تعاملی معمولاً فقط پس از بارگذاری کامل صفحه و مقداردهی تمام اشیاء مورد نیاز اجرا می‌شوند. نیازی به بارگذاری این اسکریپت‌ها قبل از محتوای صفحه نیست؛ این کار فقط سرعت نمایش اولیه بارگذاری صفحه را کاهش می‌دهد.

      برای بهبود کارایی، تعداد فایل‌ها را به حداقل برسانید، اما JavaScriptهای نامرتبط را برای نگهداری آسان در فایل‌های جداگانه نگه دارید.
